## 当前结论

新增 `packages/codex-client`，包名 `@jira-workbench/codex-client`，版本 `0.33.8`。它是包含本地 Core 运行代码与 MCP Apps UI 的原生预览包，尚未发布此 npm 包，不是只含协议入口、要求用户另外安装 Core 的薄安装包。

工作台、会话侧面板、设置的 `global / thread / settings` 元数据已实现；复用 Core 业务 UI，并增加同页设置。用户已确认第一轮本机预览的插件详情出现、全局工作台能打开；设置、会话侧面板、新构建交互、图标位置和 npm source 真实安装仍待验，不能据此宣布整体迁移完成。

旧 `packages/codex` 与 DSH 适配器继续保留。不修改 `F:\dsh\deepseek-harness`，默认验证不安装生产插件；本机预览安装必须明确选择。不自动重启、不自动迁移数据或读取旧凭据，不发布 npm。

本机静态审查样本是 Windows Codex `26.1002.7124.0` 与 CLI `0.147.0`；静态源码存在对应发现、加载及协议分支。没有据此确认最低 Codex 版本，也没有确认所有账号、系统和桌面模式都支持全部入口。

实机验收准备时确认：当前桌面后端实际为 CLI `0.162.0-alpha.2`，PATH 的 `0.147.0` 不是同一运行时。已用该桌面后端通过隔离安装探针；持久预览安装与桌面交互结果单独记录于[实机验收清单](codex-native-acceptance.md)。

## 目标架构

```text
官方 Plugin / MCP Apps 工作台与设置
             ↕ 官方桥接
       各宿主 STDIO 薄协议桥
             ↕ 认证 loopback
       单实例受管理 Core
             ↕
      Jira / 附件 / SVN / 本地状态
```

官方入口和 MCP Apps 桥接承担 UI 承载，不修改宿主安装文件或扫描 DOM。STDIO 薄桥不持有独立业务状态，不给每个窗口创建第二个 Core 写者。原生 App Server 是建立自有客户端的协议能力，不能直接等同于挂入现有桌面窗口 UI 或获得当前原生会话的关联回执。

数据默认隔离到 `%LOCALAPPDATA%\jira-workbench\codex-native-preview`。配置、会话关联文件、目录绑定、SVN baseline / review 和附件等持久路径显式传入 Core，不能因旧适配器环境变量而落到现有生产数据目录。后续如需迁移，要另设计用户确认、备份和回滚，不隐式导入。

确定性 loopback 端口的监听权是操作系统级单实例约束。只接受本机、正确 Host、正确 Bearer 且无浏览器 Origin 的请求；不向外网暴露，不允许 UI 绕开官方桥接直接浏览服务。端点记录包含凭据，不能写入页面、日志或文档示例。

最后一个 STDIO 连接退出并不意味着业务已结束：服务必须同时检查租约、请求、实际工具 handler 和后台 SVN 操作。所有写操作结束前保持监听权；失败的写请求不自动重放。

| 能力 | 预览合同 | 还需要的验收 |
| --- | --- | --- |
| 全局工作台 | 已声明 `global` 工具及 UI 资源 | 官方图标、首开、重开、多窗口 |
| 会话侧面板 | 已声明 `thread` 工具及资源 | 实际侧面板展示、切换与尺寸；不等于会话关联 |
| 设置 | 已声明 `settings`；工作台同页设置 UI | 官方设置入口、保存回读、冲突、暗色与窄屏 |

| 目录绑定 / SVN | Core 工具、确认及审核流程复用 | 多目录、取消、TortoiseSVN、失败恢复、实际提交人工验收 |
| 原生项目列表 | `projectCatalog: false` | 公开合同与可信数据源确认 |
| 当前会话上下文 | `sessionContext: false` | 真正 threadId、目录、身份范围与回执确认 |
| 新建 / 绑定会话 | `conversationCreation / conversationBinding: false` | 创建后才绑定、回执、失败恢复与幂等确认 |
| 宿主 Skill | `skills: false` | 官方列表、项目可用性与实际执行验证 |
| 自动刷新任务 | 新代码 `taskAutoRefresh: true`；面板内只读刷新、暂停、去重、退避及设置回写已实现 | 新构建安装后的定时、页面可见性与返回同步实际验收；不是后台服务监控 |
| 自动化 / 自动更新 | `automation / automaticUpdates: false` | 独立设计及验收，不借设置保存冒充启用 |

项目目录可手动配置，`workspaceBinding: true` 不代表已读取原生项目列表。同样，同页设置不代表已实现宿主自动生成的结构化设置 schema。

2026-10-09 新代码支持可编辑的任务定时 / 返回可见面板同步，未支持的 Sheets 后台同步与更新策略保留但不启用。真实桌面目前仍安装 2026-10-08 构建，不能用新代码的能力声明代替本机生效验证。配置 revision 改变清理旧列表缓存；自动响应只在原页面和配置仍有效时回写，不覆盖较新的手动刷新或导航。

设置增加 Jira 项目 / Filter 的只读选项工具，保持已选 ID、使用保存凭据、revision 检查、查询单飞及整体取消预算。这是 Jira 目录，不是 Codex 原生项目列表。图片适配新增请求去重、原始尺寸；非图片仅通过官方链接在 Jira 查看，本地首次下载 / 二次打开仍未迁移。

写工具对模型采用 `app-only` 可见性，保留 Core 原有一次性确认、审核快照和最终人工确认。可见性策略不是可信用户身份，不得移除服务端保护。设置保存须用户明确确认与 revision 校验，读取结果须脱敏，PAT / Webhook 不回显。

## 回归清单

- 安装：解包路径、缺 Node、缺资源、无需 lifecycle 构建、包版本与 manifest 同步、全新隔离目录首次启动。
- 生命周期：多连接共用一实例、并发启动、端口冲突不杀进程、租约释放、空闲退出、断连后工具仍在执行、后台 SVN 仍在执行。
- 安全：无 Token / 错 Token / 错 Host / 带 Origin 拒绝；凭据不进 UI 与日志；生产旧状态不被读取或覆盖；写请求不重放。
- 入口：三个入口真实展示，首开 / 重开 / 会话切换，暗色 / 高 DPI / 窄面板，关闭后不留下挡住会话的 UI。
- 工作台：页签与返回、面板区域稳定、Sheets 表格目录完整、Filter 可见性、父子单需求上下文、刷新与失败反馈。
- 附件：原图清晰度、放大、左右切换、下载后再次打开、图片不支持时的已定义降级；不因 Core UI 复用就认定宿主图片路径已通过。
- 设置：同页打开、锚点定位、保存后回写、PAT 留空保留、脱敏、revision 冲突不覆盖、取消不写入、失败后可重试；禁用自动同步控件且保存时保留原值，明确使用手动刷新。
- SVN：按所选目录、单击差异与双击 TortoiseSVN、一致布局、区域内遮罩、快照失效、审核结果处理、一次性确认、最终复核与失败恢复。
- 能力提示：原生项目 / 会话 / Skill / 自动化不可用时明确禁用，不出现伪造绑定成功或空列表假装加载成功。

涉及真实 Jira 写操作、SVN 提交、模型调用和创建会话的测试，应由用户明确验收授权后执行；隔离 smoke 不能操作生产业务数据。

## 会话能力后续阻碍

现有公开 UI 资料没有证明能够读取真实当前 threadId、列出原生项目或在现有桌面窗口创建并返回可信会话关联结果。匿名 session 标识不能作为真实 threadId；打开 deep link 不能作为发送成功回执。不要通过扫描会话日志或私有宿主状态恢复一个未经确认的“原生接口”。

2026-10-09 核对官方 Hooks：受信任的插件生命周期 hook 可收到 `session_id` 与 `cwd`，但它们表示触发事件的会话，不能用“最后触发的会话”猜当前聚焦聊天；子代理事件可能使用父会话 ID。插件安装不自动信任 hooks，须用户在宿主审核。后续可做显式登记 / 用户选择方案，当前未加入 hook、未绕过信任步骤，`sessionContext / conversationBinding` 仍为 false。App Server 的公开 `thread/read`、`thread/list`、`skills/list` 不等于已取得现有桌面运行中的客户端连接或创建回执。

用户信任的 Hook 可作为后续会话信息登记方案研究，但目前只属于可行性推论，尚未实现与验收；不能在能力状态里提前标为支持。App Server 的独立客户端方案也要单独验证与现有窗口的关系。找到可靠合同前，保持相关能力 `false`，向用户说明影响。

## 何时退出旧 CDP 路径

只有真实桌面 UI、完整安装包、干净环境安装与核心工作流验收通过，且会话 / 目录 / Skill 等缺口有用户接受的处理结果后，才决定默认入口切换。正式切换还需要备份与可恢复数据迁移、回滚方案和明确用户确认。

不为制造“迁移完成”删除仍服务用户的旧适配器、不把部分能力永久隐藏后宣称全量替代、不静默注入作为原生验收失败的后备。DSH 保持独立，不修改其工程。
